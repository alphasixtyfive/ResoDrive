# ResoDrive / HASS Connect review, September 2026

HASS Connect at `59f050a` uses WinUI; ResoDrive uses WPF. Its useful patterns are
compact dialog composition, consistent product metadata, standard links and
services separated from view code. Keeping those patterns consistent does not
require replacing ResoDrive's UI framework or working installer.

## Implemented

- About now follows the HASS Connect hierarchy: 48-pixel mark, product name and
  version grouped vertically, wrapping attribution and three standard navigation
  links. Removed the custom link-button template and four duplicate handlers;
  links support keyboard focus and Escape closes the dialog.
- Wipe coordination is a separate durable state machine instead of inline,
  one-shot shutdown cleanup. A shared account-write guard protects settings and
  setup transactions. Protocol checks, process shutdown, cleanup and persistence
  have separate responsibilities and failure tests.
- Found and corrected omitted backup/staging files, acknowledgement retry gaps,
  subdirectory/port handling, unlimited response-body reads and the registration
  catalog's accidental single-password size limit.
- Security setup text and the [administrator guide](REMOTE-WIPE.md) state the
  all-account wipe scope and limitations explicitly.

## Worth doing next

1. Isolate credentials and caches per account, with a migration that preserves
   queued uploads. Then make wipe account-specific. This is the largest remaining
   security/design improvement; changing just the deletion path would be unsafe.
2. Use Nextcloud Login Flow v2 for enrollment and expose per-account enrollment
   status. This would reduce manual password mistakes and make missing protection
   visible without adding a permanent banner to every drive row.
3. Continue extracting settings/setup orchestration from the large main window
   behind tested services. Do this by behavior, retaining the existing host and
   settings transaction boundaries.
4. Add signed release binaries and a repeatable disposable Nextcloud integration
   environment. Checksums and mocked HTTP tests do not replace either.

Avoid cosmetic rewrites of the working updater/installer in this pass. Preserve
the UAC, installed-lifecycle and populated-window release gates documented in
[RELEASING.md](RELEASING.md).
